CSS Selectors, Combinators & Specificity

Module: 04. Element Targeting & Cascade Resolution

Description: An exhaustive technical reference for targeting Document Object Model (DOM) nodes in CSS. Covers basic selectors, structural combinators, attribute operators, interactive and tree-structural pseudo-classes, the revolutionary parent selector (:has), virtual pseudo-elements, and the mathematical 4-column specificity algorithm.

1. Basic Selectors (Universal, Type, Class, ID)

Def: The fundamental targeting mechanisms in CSS that query elements based on their HTML tag name, class attributes, unique ID identifiers, or universal wildcards.

1.1 Universal Selector (*)

Def: A wildcard selector that matches every single HTML element on the entire page across all nesting depths.

Specificity Weight: (0, 0, 0, 0) — Has zero specificity weight.

Primary Production Use: Setting baseline resets like box-sizing: border-box;.

Syntax:
* { box-sizing: border-box; margin: 0; }

1.2 Type (Element Tag) Selector

Def: Targets all HTML nodes that share the specified tag name (e.g., p, h1, button, table).

Specificity Weight: (0, 0, 0, 1) — 1 Element point.

Production Role: Establishes global default typography and baseline component styles before classes are layered on top.

Syntax:
p { line-height: 1.6; }
h2 { letter-spacing: 0.5px; }

1.3 Class Selector (.class)

Def: Targets all HTML elements that contain the specified class name inside their class="..." attribute. Denoted with a leading period (.).

Specificity Weight: (0, 0, 1, 0) — 1 Class point.

Industry Standard: Classes are the primary workhorse of production CSS architecture (BEM, utility systems, component libraries) because they are reusable and maintain manageable specificity.

Syntax:
.btn-primary { background-color: #2563eb; }

1.4 ID Selector (#id)

Def: Targets the single unique element on the page that has the matching id="..." attribute. Denoted with a leading hash (#).

Specificity Weight: (0, 1, 0, 0) — 1 ID point (100x stronger than a class).

Architectural Warning: Because IDs carry overwhelmingly high specificity, using them for general CSS styling makes rules nearly impossible to override without writing fragile code. In modern frontend engineering, IDs are reserved for JavaScript hooks and in-page anchor navigation links (e.g., href="#section").

Syntax:
#site-header { position: sticky; top: 0; }

2. CSS Combinators (Relationship Selectors)

Def: Characters that express specific structural relationships between two or more selectors in the DOM tree hierarchy.

Combinator Name Symbol Relationship Required Code Pattern
Descendant Selector (Single space) Matches target anywhere inside the ancestor, regardless of nesting depth. article p
Child Combinator > Matches only direct, immediate first-level children of the parent. ul > li
Adjacent Sibling Combinator + Matches an element that appears immediately after another element at the same hierarchy level. h2 + p
General Sibling Combinator ~ Matches all siblings that appear anywhere after the target at the same hierarchy level. h2 ~ p

2.1 Descendant (Space) vs. Child (>) Combinator

The Difference: The space combinator reaches down through infinite layers of nested elements. The child combinator (>) strictly stops at the very first inner level.

e.g.
nav a { color: blue; } /* Targets all links inside nav, even inside sub-menus */
nav > a { color: blue; } /* Targets ONLY top-level direct link children */

2.2 Adjacent Sibling (+) vs. General Sibling (~)

Adjacent Sibling (+): Selects the single element positioned directly next door. Very common for adding top margins to paragraphs that follow headings (e.g., h2 + p).

General Sibling (~): Selects every matching sibling positioned anywhere after the first element, provided they share the exact same parent container.

3. Compound Selectors & Selector Grouping

Def: Techniques for chaining multiple selectors together to target specific combinations, or grouping separate rules to share styling declarations.

3.1 Compound Selectors (Chaining without Spaces)

Def: Writing multiple selectors chained directly together with zero spaces between them. The browser requires the element to satisfy all conditions simultaneously.

Important Difference:

  • p.warning (No space): Matches a <p> element that also has class="warning".
  • p .warning (With space): Matches any element with class="warning" that sits inside a <p> tag.

e.g.
button.btn.btn-primary.active { background-color: #1e3a8a; }

3.2 Selector Grouping (Comma List)

Def: Comma-separated list of distinct selectors that share the exact same declaration block.

Syntax:
h1, h2, h3, h4, h5, h6 { font-family: sans-serif; font-weight: 700; }

The Selector List Pitfall: In standard CSS, if a single selector in a comma-separated list is invalid or unsupported by a browser, the entire rule block is thrown out by the engine. (See modern :is() below to avoid this issue).

4. Attribute Selectors

Def: Targets HTML elements based on the presence, exact value, or partial substring match of their HTML attributes (such as type, href, src, target, or disabled).

Selector Pattern Matching Rule Real-World Production Example Target Description
[attr] Presence input[required] Matches any input that possesses the required attribute, regardless of its value.
[attr="val"] Exact Match input[type="password"] Matches inputs where the type attribute is exactly equal to "password".
[attr~="val"] Whitespace-separated Word [class~="card"] Matches if "card" appears as a whole word in a space-delimited list of words.
[attr^="val"] Prefix (Starts With) a[href^="https://"] Matches all secure external links whose URL starts with "https://".
[attr$="val"] Suffix (Ends With) a[href$=".pdf"] Targets all direct links pointing to PDF files to append a document icon.
[attr*="val"] Substring (Contains) img[src*="avatars"] Matches any image whose source path contains the word "avatars" anywhere inside.
[attr="val" i] Case-Insensitive Match a[href$=".jpg" i] Matches filenames ending in .jpg, .JPG, .Jpg without case conflicts.

5. Pseudo-Classes (:state & :structural)

Def: Keywords added to a selector that specify a special state of the targeted elements (such as user interaction states, form validation states, or DOM hierarchy position). Always prefixed by a single colon (:).

Specificity Weight: (0, 0, 1, 0) — Exactly equal to one class selector.

5.1 User Action & Interaction States

Pseudo-Class Trigger Condition Production Standard Rules
:hover User places the mouse pointer over the element. Must never be the only way to access content (touch screens have no hover).
:active Element is currently being pressed down by mouse click or tap. Used to provide tactile "pressed button" feedback.
:focus Element has received keyboard or input focus. Critical for accessibility. Highlights active form inputs and buttons.
:focus-visible Element receives focus via keyboard navigation (Tab key). Modern standard: suppresses focus rings on mouse click while preserving them for keyboard users.
:focus-within Element itself or any child inside it has received focus. Used to highlight an entire card or form when an inner input is active.

The LVHA Link Order Rule

When styling links, state rules must be declared in this exact order to prevent cascade conflicts: :link → :visited → :hover → :active (Mnemonic: Lord Vader Handle Arms).

5.2 Tree-Structural Pseudo-Classes (DOM Tree Position)

Pseudo-Class Target Condition Critical Difference / Gotcha
:first-child Target is the very first child of its parent. Fails completely if a different tag (like an <h1>) sits before the target element.
:first-of-type Target is the first of its specific tag type among siblings. Ignores other sibling tags and looks strictly for the first occurrence of that tag.
:last-child Target is the absolute last child of its parent. Matches only if no other child follows it.
:last-of-type Target is the last occurrence of its tag type among siblings. Bypasses any trailing elements of different types.
:only-child Target has zero siblings (it is the sole child in the container). Useful for removing margins when an element sits alone.
:nth-child(An+B) Matches elements based on an algebraic cycle formula. Counts all children regardless of tag type.
:nth-of-type(An+B) Matches elements based on a cycle among identical tags. Filters strictly by tag type before counting.

The Math of :nth-child(An+B)

The variable n is an integer counter starting at 0, 1, 2, 3...

  • :nth-child(odd) or :nth-child(2n+1): Matches 1st, 3rd, 5th, 7th elements (zebra-striping tables).
  • :nth-child(even) or :nth-child(2n): Matches 2nd, 4th, 6th, 8th elements.
  • :nth-child(3n): Matches every 3rd element (3, 6, 9...).
  • :nth-child(-n+3): Matches only the first 3 elements.

5.3 Modern Functional Pseudo-Classes (:is, :where, :not, :has)

Def: Advanced CSS selectors that accept selector lists inside parentheses, fundamentally simplifying complex stylesheets.

Functional Selector Role & Function Specificity Behavior
:is(h1, h2, h3) Matches any element in the list. Forgiving (invalid selectors inside do not break the rule). Adopts the specificity of its highest-weighted argument.
:where(h1, h2, h3) Exact same matching role as :is(), but eliminates specificity completely. Always (0, 0, 0, 0). Ideal for CSS reset files and design system component defaults that can be easily overridden.
:not(.active) Negation. Targets every element that does not match the argument. Adopts the specificity of the selector inside the argument.
:has(> img) The Parent Selector: Matches an element if any element matching the argument exists inside it. Adopts the specificity of its highest-weighted inner selector.

The Power of the :has() Relational Selector

Before :has(), CSS could only style downwards (parents styling children). The :has() pseudo-class allows parents to style themselves based on their children's state:

/* Styles a card container only if it contains an image */
.card:has(img) { grid-template-rows: 200px 1fr; }

/* Styles a form label if the input next to it is focused */
label:has(+ input:focus) { color: #2563eb; }

6. Pseudo-Elements (Virtual DOM Nodes)

Def: Keywords added to a selector that allow developers to style specific parts of an element's content or insert virtual, decorative elements into the DOM tree. Modern CSS syntax uses a double colon (::) to distinguish pseudo-elements from pseudo-classes.

Specificity Weight: (0, 0, 0, 1) — Exactly equal to one type (element) selector.

6.1 ::before and ::after (Generated Content)

Def: Inserts a virtual child element inside the targeted element, positioned directly before or after the element's actual content.

The Mandatory Requirement: Both ::before and ::after require the content: ""; property to be declared. Without content, the virtual element is never created by the browser.

Default Display: Rendered as display: inline; by default. To set width and height, they must be set to display: block; or display: inline-block;.

Syntax:
.badge::before { content: "• "; color: green; }

6.2 Essential UI Pseudo-Elements

Pseudo-Element Target Region Common Design Application
::first-letter The very first character of the first line of text. Creating editorial drop-caps in magazine articles.
::first-line The first formatted visual line of a paragraph. Styling opening lead text in news stories.
::selection The text highlighted by the user's cursor drag. Customizing brand highlight colors on selected text.
::placeholder The ghost placeholder text inside an <input>. Adjusting input placeholder color and opacity.
::marker The bullet point on <li> items or the arrow on <details>. Coloring list bullets without creating custom markup.

7. The Specificity Calculation Algorithm

Def: The mathematical weighting system used by the browser cascade to decide which CSS declaration wins when multiple selectors target the exact same HTML element.

7.1 The 4-Column Specificity Tuple (A, B, C, D)

Specificity is calculated as a 4-part score (A, B, C, D). It is compared column by column from left to right. A single point in a higher-order column completely outweighs any number of points in lower columns (e.g., 1 ID beats 1,000 classes):

Column Weight Category What Matches This Category Score Value
Column A Inline Styles Styles written directly inside HTML via style="..." (1, 0, 0, 0)
Column B ID Selectors IDs starting with # (e.g., #main-nav) (0, 1, 0, 0)
Column C Classes, Attributes & Pseudo-classes Classes (.btn), attributes ([type="text"]), pseudo-classes (:hover) (0, 0, 1, 0)
Column D Elements & Pseudo-elements Tags (p, div), pseudo-elements (::before, ::after) (0, 0, 0, 1)
Zero Score Universal, Combinators & :where *, combinators (+, >, ~, space), and :where() (0, 0, 0, 0)

7.2 Worked Specificity Calculation Examples

Selector String Column A (Inline) Column B (IDs) Column C (Classes) Column D (Tags) Final Tuple Score
* 0 0 0 0 (0, 0, 0, 0)
p 0 0 0 1 (0, 0, 0, 1)
div ul li a 0 0 0 4 (0, 0, 0, 4)
.card .btn 0 0 2 0 (0, 0, 2, 0)
nav > ul > li.active > a:hover 0 0 2 4 (0, 0, 2, 4)
#header .nav-item a 0 1 1 1 (0, 1, 1, 1)
<p style="color: red;"> 1 0 0 0 (1, 0, 0, 0)

The Nuclear Option: !important

Appending !important to a declaration takes it outside the standard specificity competition entirely. An !important declaration overrides everything, including inline styles. The only way to override an !important rule is with another !important declaration that has higher specificity or appears later in the source code.
